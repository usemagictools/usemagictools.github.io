Frequently Asked Questions

In LLM token generation (decoding phase), the model has to process one token at a time. For each generated token, the GPU or CPU must read the entire model weights (several gigabytes) from memory into its caches. Because this must happen for every single token, the generation speed is heavily limited by how fast your hardware can read from memory (Memory Bandwidth), rather than raw compute power (FLOPS).

The theoretical maximum speed (Tokens per Second) during the decoding phase is calculated using the formula: Speed = Memory Bandwidth (GB/s) / Model Size (GB). For example, if you run a Q4 quantized Llama 3 8B model (size ~4.5 GB) on a standard Mac Mini M4 (bandwidth 150 GB/s), your maximum bandwidth-limited speed is: 150 / 4.5 ≈ 33.3 tokens/second.

On PCs with dedicated graphics cards (like RTX 4070), if the model exceeds the GPU's VRAM (e.g. 12GB), the system is forced to offload the remaining layers to system memory (DDR4/DDR5) via the PCIe bus. Since system RAM bandwidth (approx 50-80 GB/s) is 10 times slower than VRAM, your generation speed will instantly collapse to 1-3 tokens/second (OOM bottleneck). On Mac, unified memory acts as both, avoiding PCIe bottlenecks but still limited by total capacity.

Yes. The formula Speed = Bandwidth / Model Size applies to single-user generation (Batch Size = 1). As batch size increases (e.g., serving multiple users concurrently), the bottleneck shifts from Memory Bandwidth to GPU Compute Power (FLOPS), because the compute workload per loaded weight multiplies, allowing the hardware to utilize its raw processing cores more efficiently.
